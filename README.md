# Лендинг для натяжных потолков + админка заявок

Одностраничный сайт для бригады монтажников натяжных потолков с квизом-калькулятором,
портфолио «до/после» и админкой для приёма заявок.

## Что внутри

- **Лендинг** — 10 блоков, квиз-расчёт стоимости (4 шага), галерея «до/после»
  с перетаскиваемым ползунком и полноэкранным просмотром, отзывы, FAQ.
- **Квиз** — считает ориентировочную стоимость по площади, типу потолка и светильникам.
- **Админка** `/admin` — заявки со статусами (новая / в работе / обработана / отказ),
  статистика, фильтры, кликабельные телефоны.
- **Уведомления** — заявка сохраняется в SQLite и дублируется письмом (если настроен SMTP).

## Стек

Чистый HTML/CSS/JS на клиенте + Node.js 24 (Express 5, `node:sqlite`, nodemailer, bcryptjs).
Без сборщика. Страница весит ~36 КБ HTML + 11 КБ JS, изображения 311 КБ (WebP).

## Запуск

```bash
npm install
cp .env.example .env    # Windows: copy .env.example .env
npm start
```

- Сайт: http://127.0.0.1:3000
- Админка: http://127.0.0.1:3000/admin

При первом запуске генерируется пароль администратора и сохраняется в
`data/admin-password.txt`. Либо задайте свой через `ADMIN_PASSWORD` в `.env`.

## Настройка почты

Заполните в `.env`:

```
MAIL_TO=owner@example.ru

SMTP_HOST=smtp.yandex.ru
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=noreply@example.ru
SMTP_PASS=пароль_приложения
MAIL_FROM=noreply@example.ru
```

Для Яндекс.Почты и Mail.ru нужен **пароль приложения**, а не основной пароль от аккаунта.

Если почта не настроена — заявки всё равно сохраняются и видны в админке.

## Тесты

```bash
node e2e.mjs        # лендинг: 33 проверки
node admine2e.mjs   # админка: 16 проверок
```

Требуется запущенный сервер и установленный Chromium для Playwright:

```bash
node node_modules/playwright/cli.js install chromium
```

## Структура

```
index.html          лендинг (разметка + стили)
main.js             конфиг клиента, квиз, валидация, отправка заявки
admin.html          админка
admin-login.html    страница входа
server.js           Express: API заявок, админка, статика
db.js               SQLite: заявки, настройки, сессии
img/                изображения WebP
data/               база и пароль админки (не в git)
```

## Настройка под клиента

Почти всё меняется в объекте `CONFIG` в начале `main.js`:

```js
const CONFIG = {
  brand: 'ПотолокПро',
  phone: '+7 (978) 000-00-00',
  phoneRaw: '+79780000000',
  whatsapp: '79780000000',
  email: 'info@example.ru',
  apiUrl: '/api/lead',
  metrikaId: 0,
};
```

Цены и варианты квиза — в объекте `PRICES` там же.

## Безопасность

- Пароль администратора хранится как bcrypt-хеш, сессии — в БД, cookie `httpOnly`.
- Ограничение частоты: 5 заявок и 10 попыток входа на IP за 10 минут.
- Служебные файлы (`.env`, `data/`, `server.js`, `db.js`) недоступны по HTTP.
- Секреты только в `.env`, никогда в коде.

## Две версии

**1. Демо-витрина (GitHub Pages)** — папка `docs/`
Статика без сервера: работает квиз, галерея, лайтбокс. Отправка заявки — через
Formspree (вставьте URL в `CONFIG.formspreeUrl` в `docs/main.js`).
Пока не настроено — форма честно показывает демо-сообщение.

**2. Полная версия (сервер)** — корень репозитория
Лендинг + админка заявок + SQLite + письма. Запуск: `npm start`.
Деплой: Render (`render.yaml`), Amvera, VPS.
